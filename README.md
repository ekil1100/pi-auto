# pi-auto

`pi-auto` 是一个 Pi 扩展：每次开始新的任务时，自动选择当前模型的 thinking effort，再让 Pi 执行任务。**不自动选择或切换模型。**

## 工作方式

1. 读取当前模型及其实际支持的 effort，不依赖 scoped models。
2. 只有一个可用 effort 时直接使用，例如非推理模型使用 `off`，不额外调用模型。
3. 使用当前模型发起一次独立的 effort 判断请求：优先使用 `low`；不支持 `low` 时使用最低的可用非 `off` 档位。
4. 判断依据是当前任务、有效会话中的近期文本和摘要，以及是否包含图片；只接受模型支持的 effort。
5. 验证后只调用 `pi.setThinkingLevel()`，不调用 `pi.setModel()`。
6. 超时、鉴权错误、输出截断或无效输出时保留当前 effort，不中断原任务。等待期间用户切换模型、调整 effort 或关闭自动选择时，不应用过期的判断。

## 为什么判断请求不默认使用 off

**判断用的 effort 和执行用的 effort 是两回事。** 即使主任务当前是 `off`，判断请求仍独立使用 `low`（或模型支持的最低非 `off` 档位），随后可以为主任务选择 `off`、`high` 等任一受支持档位。

`off` 并不等于模型没有判断能力，可以用来做简单任务分类；但这不代表它能可靠识别隐藏复杂度，更不能仅凭自评知道哪个 effort 最优。短提示、模糊调试和跨文件任务尤其容易被低估。这里保留 `low` 作为初始策略，并在提示中要求信息不足时偏向 `medium/high`，而不是把不确定当成简单。

默认选择目标是“匹配任务需求、能可靠完成任务的最合适 effort”，不是一律降低 effort：

| Effort | 典型任务 |
| --- | --- |
| `off/minimal` | 查找、格式整理、方案明确的机械修改 |
| `low` | 范围明确的小修改、直接问答 |
| `medium` | 常规实现、调查、多步骤工作 |
| `high` | 模糊调试、架构、较大重构、安全敏感任务 |
| `xhigh/max` | 异常困难、高风险、跨范围很广的任务 |

这是启发式分流，尚未用真实任务评测证明 `low` 优于 `off`。比较判断策略时，应固定执行模型，记录任务成功率、重试次数、总延迟和 token 用量，不能只比较判断请求本身的成本或模型给出的理由。

## 安装与试用

在仓库目录直接试用：

```bash
npm install
pi -e .
```

安装为本地 Pi package：

```bash
pi install /absolute/path/to/pi-auto
```

通过 Pi 的 `/model` 手动选择模型即可，无需配置 `/scoped-models` 或 `enabledModels`。这些设置仍由 Pi 自己使用，但不参与 pi-auto 的 effort 判断；其中的 `:high` 等后缀也不再作为 pi-auto 的固定 effort 限制。

## 命令

```text
/auto
/auto toggle
/auto on
/auto off
/auto status
```

`/auto` 和 `/auto toggle` 切换开关；`on`、`off` 显式设置开关；`status` 查看当前模型、当前及可用 effort、最近一次判断和理由。

开启时底栏显示 `auto · low` 等当前状态：`auto` 使用主题主色（`accent`），effort 使用 Pi 对应的思考等级颜色。手动切换模型或 effort 后同步更新，关闭自动选择后隐藏。开关只作用于当前扩展实例，重启或重载后默认开启。

## 选择记录

- 任务开始时显示主题色 spinner 与 `choosing effort` 临时进度行，判断结束后移除。
- 判断完成后移除进度行，在对话历史中保留一条彩色的 `auto · low` 记录，默认折叠；即使 effort 不变也会记录。
- 按 Pi 原生 Ctrl+O 展开或折叠详情，与工具输出共用展开状态，快捷键提示遵循用户的键位配置。详情包含模型、前后 effort、判断模型与 effort、理由和耗时。
- 失败时保留原 effort，记录标记为 `kept`；选择期间关闭自动选择会取消等待，记录标记为 `cancelled`，迟到结果不会生效。
- 记录使用 Pi 的自定义 entry，不进入模型上下文。普通会话会保存记录，恢复会话后仍可展开；`--no-session` 只在当前进程内保留，退出后不保存。旧版的临时通知不会补录。
- 自定义折叠渲染用于交互终端；其他客户端可读取 entry 数据自行展示。

`/auto off` 是关闭自动选择，不是把任务 effort 设为 `off`。需要固定 effort 时，先 `/auto off`，再使用 Pi 自带的 `/thinking` 调整。

## 行为与限制

- 自动选择发生在 `before_agent_start`，作用于即将开始的任务；不会在工具循环中途重新判断。
- 不再为候选模型做图片兼容性或上下文窗口筛选。当前模型的能力、上下文压缩仍由 Pi 管理，上下文用量未知也不会阻止 effort 判断。
- 判断请求只发送最多约 12,000 个字符的当前任务、最多约 6,000 个字符的有效上下文中近期用户/助手文本及会话摘要。过长文本保留首尾、裁剪中段。
- 图片只发送“是否存在”的标记，不发送图片数据，也不发送工具结果原文。图片检查覆盖当前附件以及压缩后有效上下文中的用户、工具结果和扩展上下文消息，不计入已移除或其他分支的图片。因此不能仅靠图片标记准确判断视觉任务难度。
- 判断通过当前 provider 的 `streamSimple()` 调用，使用 Pi 解析的鉴权、headers、base URL 和环境，并由 SDK 把统一的 effort 映射为供应商参数。
- 等待判断最多 20 秒；向 SDK 传入最多 2,048 token 的输出预算（不超过模型自身上限）。部分适配器会额外分配 thinking token，Codex 适配器不传递 `maxTokens`，所以它不是跨供应商的硬性总 token 上限。超时后不应用迟到结果；底层工作能否立即停止取决于鉴权流程及供应商是否响应取消。
- 独立判断调用目前不会计入 Pi 会话 footer 的主调用用量统计，但仍会产生供应商实际用量。

## 开发

```bash
npm test
npm run check
```

核心 effort 判断位于 `src/router.ts`，Pi 生命周期适配位于 `src/index.ts`，选择记录与状态渲染位于 `src/selection-ui.ts`，近期会话裁剪位于 `src/session-context.ts`。
